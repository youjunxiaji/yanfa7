# 齿轮载荷

## 业务背景

从网页版（tmb_web_v1「研发七部 → 效率工具 → 齿轮载荷」）搬来，计算原样照搬；还没发版，网页版还在用，两边要算得一样。
输入各级齿轮（行星级 Planetary / 平行级 Helical）的参数和多组输入扭矩、转速（多工况），算每一级的齿轮载荷 9 项、
部件转速 3 项、等效直径 3 项；多工况可以导出 Excel；输入可以存成 TMB 服务器上的历史记录，网页版和这边互相能回填。
和网页版不一样的：级数不限（网页版写死 4 级），页面按工具页骨架重新排过，改了参数自动算到最后一级。

## 数据流

```text
参数栏：项目三项 + 粘贴工况（扭矩、转速两列）+ 功率 + 逐级填的参数 → stores/gearLoad.ts 的输入表
→ 参数一改（停手 300 毫秒）→ POST /api/gear-load/calculate → CalGearLoads.cal()
  → 前端把上一级的功率、输出扭矩、输出转速填到下一级，再算，直到填的值不再变 → 结果区
→「导出 Excel」→ 选保存位置 → POST /api/gear-load/export → getExportData() 逐个工况算 → workbook.py 写 xlsx
→「保存配置」/「历史记录」→ /api/gear-load/histories → common/tmb_web.py 转发 TMB 服务器（见 TMB 账号参考）
```

## 业务约定

### 输入表

- 沿用网页版的写法：一行一个参数，参数名是网页版的英文原名（前端 `constants/gearLoad.ts` 的 `InputParam`），
  各级的值是字符串、空串是没填。后端按参数名取值，历史记录存的也是这张表，参数名一个字都不能改。
- 各级的键：前 4 级沿用网页版的 stageI、stageII、stageIII、stageIIII，第 5 级起接 stageV、stageVI……
  （后端 `cal_gearLoads.py` 的 `stage_keys`，前端 `stageKey`）。页面上的级名是 I、II、III、IV、V……，
  第 4 级显示成 IV，键还是 stageIIII；导出 Excel 的表名是键。
- 输入表里的级要从 stageI 起连着排，不然接口回 422；行里不是级的键丢掉，免得被当成一级。
- 网页版只认前 4 级：这边存的 5 级以上的记录，网页版打开只显示前 4 级，点「计算结果」报 IndexError（500），不管。

### 计算

- `module/cal_gearLoads.py` 是网页版 `shanghai_yanfa7/utils.py` 的原代码：`Excel` 类的属性名是单元格号（E12……E84），
  公式、写法都没改，只把写死的 4 级换成按输入表有几列生成。
- 后端算几级看有几列 16 行都非空：有 N 列就算 Stage I 起的前 N 级。Helical 级用不到的太阳轮齿数、行星轮数、KY，
  以及哪个公式都没用到的功率、旋向，也要填，页面上把用不到的三项灰掉并写了说明。
- 下一级的扭矩、转速取上一级的输出（输出扭矩 E41；行星级取太阳轮转速 E46，平行级取小齿轮转速 E47），
  用的是四舍五入到 3 位小数后的值，功率原样传下去。
- 二级以后的功率、扭矩、转速要非空，后端才把这一列算进去，网页版要等前端填上，所以 N 级要点 N 次。
  这边 `stores/gearLoad.ts` 的 `calculate` 算完一轮就 `fillChained` 填上接着算，填的值不再变就停，后端规则没改。
- 结果保留 3 位小数；这一级没有这一项、算不出来的是空串（表里显示 —），除以 0 是 "Infinity"（显示 ∞）。
  每次算完整个换掉结果，没算到的级留空。
- 有一级没填全，后端只算到它（它的结果大多是空的），后面的级不算；结果区工具栏写明是哪一级，级名旁有黄点。

### 多工况

- 「粘贴工况」一次收扭矩、转速相邻两列，每行按 tab 切开取前两格，两格都是数才算一组，数字原样留着字符串。
- 结果区右上角选看哪一组，Stage I 的扭矩、转速就是这一组的（输入表 stageI 那两格）；导出时所有组逐个算。

### 导出 Excel

- 网页版在浏览器里用 xlsx 库生成后下载；这边先用垫片的 `saveFileDialog` 选保存位置（默认文件名是项目三项），
  后端写文件，路径不是 `.xlsx` 结尾的补上。导出前先按现在的参数算一遍，二级以后的功率填好，后端才认得出有几级。
- 格式同网页版：每级一张表；第一行表头，第一格空，后面 12 个中文列名（9 项载荷 + 3 项转速，平行级也用行星级的列名）；
  每个工况一行，第一列是从 0 起的序号；列宽 8 / 15。等效直径不导出。
- 第一级按每一组工况的扭矩、转速算，后面各级取上一级的输出。`getExportData` 按位置取工况的两列，第 0 列当转速、
  第 1 列当扭矩，`ExportRequest.condition_frame` 把列顺序定死；网页版按请求里键的顺序建表，新录入的工况会对调。
- 没有多工况、Stage I 没填满时回 400；文件被 Excel 打开着（Windows 上写不进去）回 400，让关掉重试。

### 测试

- `tests/reference.py` 冻结了一份网页版原代码当参照，生产代码以后优化、改写法，这份都不跟着改。
- 网页版写死 4 级，超过 4 级的期望值由 `tests/expected.py` 逐级拼：每一级单独用参照算，上一级四舍五入后的输出接到
  下一级；4 级以内两种算法一模一样（`TestChainedReference`），拼法才可信。
- `test_calculation.py`、`test_export.py` 拿生产代码和参照对跑：常见布置（含 5、6 级）× 4 组工况，加上按固定种子随机
  生成的齿轮箱（几何参数照风电齿轮箱的量级）；结果要一模一样（容差在 `tests/compare.py` 的 `REL_TOL`）。另有几条不靠
  参照的物理关系（每级功率守恒、传动比、扭矩翻倍载荷翻倍），以及导出的每一行和页面上算这一组工况的一样。
- 用例只经 `tests/conftest.py` 的 `calculate`、`export_tables` 调生产代码：改了计算层或接口的写法，只改这两个 fixture。
- 网页版的现状单独成条，有意改的时候跟着改：下一级取四舍五入后的值（`TestChaining`）、不合理的输入算出 Infinity
  或空着（`TestDegenerate`）、算几级只看有几列填满（`test_views.py`）。
- 前端的逻辑（自动重算、填下一级、增减级）没有测试。

### 历史记录

记录按「登录的人 + 齿轮单元 + 风机 + 载荷谱」存，内容是整张输入表（二级以后的功率、扭矩、转速是算好填上的）和多工况，
报文同网页版 Ctrl+S 发的；服务器那边的规则见 TMB 账号参考。回填时输入表补齐 16 行、级数按记录里有几级，
结果区看的是 Stage I 的扭矩、转速对得上的第一组工况，回填完自动重算。

## 接口与页面

- `POST /api/gear-load/calculate`：`{inputData}`，回算到的那几级 `{stageI: {...}, ...}`；每级有 `input_data`
  （功率、输出扭矩、输出转速）、`gear_loads`、`speed_of_components`、`equivalent_diameter`，顺序同
  `constants/gearLoad.ts` 的结果行。
- `POST /api/gear-load/export`：`{inputData, selectedData, path}`，回 `{path}`。
- `GET /api/gear-load/histories?query=`、`GET /api/gear-load/histories/{id}`、`POST /api/gear-load/histories`：
  查列表、取一条、存，要登录。
- 页面 `GearLoadView.vue` 套工具页骨架，状态在 `stores/gearLoad.ts`，切页面再回来还在：
  - 标题栏右侧「保存配置」（确认框写明按三项存、同样三项会覆盖）、「历史记录」，快捷键同网页版 Ctrl+S、Ctrl+F。
  - 参数栏：项目（Gear unit、Wind turbine、Load spectrum）、工况（粘贴、组数、Power P）、齿轮级
    （`GearLoadStageEditor.vue`：I、II…… 分段切换当前级、＋ 加一级、删除最后一级，布置和旋向是分段选择，其余是数值框）；
    底部主按钮「导出 Excel」，缺前置时写明原因。
  - 结果区：工具栏是算到几级、哪一级没填全、看哪一组工况；下面是 `GearLoadResultTable.vue`，每级一列，
    分 Input data、Gear loads、Speed of components、Equivalent diameter 四组，符号前一个是 Planetary 级的、后一个是
    Helical 级的。没有工况、Stage I 没填全、出错、算的时候各有空状态。
  - 弹窗：`GearLoadConditionDialog.vue` 粘贴工况，`GearLoadHistory.vue` 历史记录。
