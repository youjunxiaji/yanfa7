# 齿轮载荷

## 业务背景

从网页版（tmb_web_v1「研发七部 → 效率工具 → 齿轮载荷」）搬来，计算和页面交互原样照搬；还没发版，网页版还在用，
两边要算得一样。输入最多 4 级齿轮（行星级 Planetary / 平行级 Helical）的参数和多组输入扭矩、转速（多工况），
算每一级的齿轮载荷 9 项、部件转速 3 项、等效直径 3 项；多工况可以保存为 Excel；输入可以存成 TMB 服务器上的
历史记录，网页版和这边互相能回填。

## 数据流

```text
基础设置 + 输入表（16 个参数 × 4 级）+「编辑多内容」弹窗（扭矩、转速两列）
→「计算结果」→ POST /api/gear-load/calculate → CalGearLoads.cal() → 各级结果
  → 前端把上一级的功率、输出扭矩、输出转速填到下一级的输入
→「保存为Excel」→ 选保存位置 → POST /api/gear-load/export → getExportData() 逐个工况算 → workbook.py 写 xlsx
→ Ctrl+S 存、Ctrl+F 查了点一条回填 → /api/gear-load/histories → common/tmb_web.py 转发 TMB 服务器（见 TMB 账号参考）
```

## 业务约定

### 计算

- `module/cal_gearLoads.py` 是网页版 `shanghai_yanfa7/utils.py` 的原代码：`Excel` 类的属性名是单元格号（E12……E84），
  公式、写法都没改。输入表按英文参数名取值（前端 `constants/gearLoad.ts` 的 `InputParam`），历史记录里存的也是这些名字，
  一个字都不能改。
- 算几级看有几列 16 行都非空：有 N 列就算 Stage I 起的前 N 级，不看填满的是哪几列；从 Stage I 往后按顺序填，
  就是填满的那几级。平行级用不到的太阳轮齿数、行星轮数、载荷系数 KY，以及哪个公式都没用到的功率、旋向，也要填。
- 下一级的扭矩、转速取上一级的输出（输出扭矩 E41；行星级取太阳轮转速 E46，平行级取小齿轮转速 E47），
  用的是四舍五入到 3 位小数后的值，功率原样传下去。后端每次都从 Stage I 链式算，但「整列填满」看的是前端发来的表：
  二级以后的功率、扭矩、转速只读，等上一次算完才由前端填上，所以新填的 N 级要点 N 次「计算结果」。
- 结果保留 3 位小数；这一级没有这一项、算不出来的是空串，除以 0 是 "Infinity"。结果表里这次没算到的级留着上一次的值。
- 会自动重算的只有：Stage I、II 改布置，Stage I 改旋向，Stage I 的扭矩或转速换一组工况；别的改动要点「计算结果」。
- 部件转速、等效直径表的第二列按 Stage I 是不是行星级取写法，不看各级自己的布置。

### 多工况

- 「编辑多内容」按列粘贴：一次只收一列（带 tab 的报错），从第一行起填，行数跟着粘贴的走，不带数字的行跳过；
  回车跳到下一行，最后一行回车加一行。
- 「确定」只留扭矩、转速都填了的行，Stage I 的扭矩、转速先取第一组。下拉框绑的是工况的序号，选一组时扭矩、转速一起换、
  马上重算；显示的是第一个值对得上的工况。

### 保存为 Excel

- 网页版在浏览器里用 xlsx 库生成后下载；这边先用垫片的 `saveFileDialog` 选保存位置，后端写文件，路径不是 `.xlsx` 结尾的补上。
- 格式同网页版：每级一张表，表名 stageI……stageIIII；第一行表头，第一格空，后面 12 个中文列名（9 项载荷 + 3 项转速，
  平行级也用行星级的列名）；每个工况一行，第一列是从 0 起的序号；列宽 8 / 15。等效直径不导出。
- 第一级按每一组工况的扭矩、转速算，后面各级取上一级的输出。`getExportData` 按位置取工况的两列，第 0 列当转速、
  第 1 列当扭矩，`ExportRequest.condition_frame` 把列顺序定死；网页版按请求里键的顺序建表，新录入的工况会对调。
- 没有多工况、Stage I 没填满时回 400；文件被 Excel 打开着（Windows 上写不进去）回 400，让关掉重试。

### 测试

- `tests/reference.py` 冻结了一份网页版原代码当参照，生产代码以后优化、改写法，这份都不跟着改。
- `test_calculation.py`、`test_export.py` 拿生产代码和参照对跑：9 种常见布置 × 4 组工况，加上按固定种子随机生成的
  齿轮箱（几何参数照风电齿轮箱的量级）；结果要一模一样（容差在 `tests/compare.py` 的 `REL_TOL`）。另有几条不靠参照的
  物理关系（每级功率守恒、传动比、扭矩翻倍载荷翻倍），以及导出的每一行和页面上算这一组工况的一样。
- 用例只经 `tests/conftest.py` 的 `calculate`、`export_tables` 调生产代码：改了计算层或接口的写法，只改这两个 fixture。
- 用例和描述齿轮箱的写法在 `tests/factories.py`，和实现无关，再换成网页版输入表的样子喂给两边。
- 网页版的现状单独成条，有意改的时候跟着改：下一级取四舍五入后的值（`TestChaining`）、不合理的输入算出 Infinity
  或空着（`TestDegenerate`）、算几级只看有几列填满（`test_views.py`）。

### 历史记录

记录按「登录的人 + 齿轮单元 + 风机 + 载荷谱」存，内容是整张输入表和多工况，报文就是网页版 Ctrl+S 发的；
服务器那边的规则见 TMB 账号参考。没登录时 Ctrl+S 先打开登录框，登录完接着存；回填只换基础设置、输入表和多工况，
结果表不动，要再点「计算结果」。

## 接口与页面

- `POST /api/gear-load/calculate`：`{inputData}`，回算到的那几级 `{stageI: {...}, ...}`；每级有 `input_data`
  （功率、输出扭矩、输出转速）、`gear_loads`、`speed_of_components`、`equivalent_diameter`，顺序同
  `constants/gearLoad.ts` 的结果行。
- `POST /api/gear-load/export`：`{inputData, selectedData, path}`，回 `{path}`。
- `GET /api/gear-load/histories?query=`、`GET /api/gear-load/histories/{id}`、`POST /api/gear-load/histories`：
  查列表、取一条、存，要登录。
- 页面 `GearLoadView.vue` 照搬网页版的上下排布：基础设置（右上角写着 Ctrl+S、Ctrl+F）、Input data（「保存为Excel」
  「计算结果」）、Gear loads、Speed of components、Equivalent diameter（默认收起），没套工具页骨架；网页版右侧的锚点导航没搬。
  状态都在组件里，切到别的页面再回来就没了。历史记录弹窗是 `GearLoadHistory.vue`。
