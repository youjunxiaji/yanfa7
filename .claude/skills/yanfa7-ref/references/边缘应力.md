# 边缘应力分析

## 业务背景

轴承仿真导出的 HTM 文件记录了各滚子列在内、外滚道上的接触应力。本模块批量解析这些文件、去掉异常尖峰，
按滚子列出报告图：内 / 外滚道应力曲线（中、英文各一张）、应力等高线图、载荷雷达图和应力雷达图，
另出一份所有文件所有列的「最大应力汇总.xlsx」，写报告时直接取用。

出图之后可以在预览窗口里看 Plotly 交互图，拖动数据点修正个别应力值，相关 PNG 和汇总表随之重画。

## 数据流

```text
选择文件夹 → scanDir 递归扫描 .htm（多次选择会追加，按路径去重）
→ 开始解析 → WS /ws/parse：后端逐文件解析、去峰、出 PNG；每个文件开始时推 progress，
  处理完推 fileDone（列号、缩略图）或 fileSkipped（原因），文件表这一行随即更新
→ 全部文件处理完：数据集存进 DatasetCache，写汇总 xlsx，推送 done
→ 预览：打开预览窗口 → GET /api/chart-data → Plotly 画原始 + 去峰曲线
→ 拖动数据点 → POST /api/update-stress-point → 重画相关 PNG 和汇总 xlsx
→ 改雷达图最小值 → POST /api/regenerate-polar → 重画该列两张雷达图
```

## 业务约定

### 预览和改点依赖最近一次解析

`DatasetCache` 是后端进程内的单例，只存最近一次解析的数据集，每次解析整体覆盖。`chart-data`、
`update-stress-point`、`regenerate-polar` 都从缓存取数：没解析过、后端重启过，或者要看的文件不在最近一次解析里，
都返回 400（「缓存数据不存在，请重新解析文件」一类提示）。

缓存要等整批文件处理完才写入，所以文件表的预览按钮在整批完成后才可用。

### 输出文件布局

- 图片写到 `{保存路径}/res-output/{组名}/`，汇总表是 `{保存路径}/res-output/最大应力汇总.xlsx`，全局一份。
- 组名取文件名里第一个 `(` 之前的部分并去掉末尾空格：`滚动轴承 1 (1.Extreme Tilt)` 的组名是 `滚动轴承 1`，
  同一轴承的不同工况落进同一目录。后端 `views.py` 的 `_get_group_name`、前端 `stores/edgeStress.ts` 和
  `ReportPreviewView.vue` 的 `getGroupName` 各算一次组名来拼路径，规则改动要三处一起改。
- 每个滚子列 8 张 PNG：内 / 外滚道各有中文、英文应力曲线和等高线图，另加载荷、应力雷达图。
  文件名格式见 README「输出文件说明」和 `EdgeStressReporter`。

### 汇总表被占用时不往下做

解析开始前和改点之前，后端都先试着以追加方式打开 `最大应力汇总.xlsx`：文件正被 Excel 打开时直接报错
（「最大应力汇总.xlsx 正被其他程序占用，请关闭后重试」），不解析、不改缓存，免得图片和汇总表对不上。

### 解析参数

- 去峰用 `scipy.signal.find_peaks`，阈值 `peakThreshold` 在参数区「数据处理」里设。
- 图片宽高和雷达图径向最小值随解析请求一起发给后端（`reportConfig`）。
- 后端的加载器也能读 Excel（store 的 `fileType` 有 `xlsx`），界面只扫描 `.htm`。

### 拖点改值

- 预览窗口里拖的是去峰后曲线上的点。前端（`usePlotlyDrag`）只回传曲线序号 `trace_index`、点序号和新值；
  曲线序号对应偏移、排序、跳过零值之后的角度，换算在后端 `update_stress_point` 里，前端不复刻这套顺序。
- 改完缓存后重画汇总 xlsx、该列该滚道的中英文应力曲线和等高线图，以及应力雷达图。

### 雷达图最小值

主页面参数区和预览窗口都能调载荷、应力雷达图的径向最小值。主页面的值存在 store 的 `reportConfig`，随解析生效；
预览窗口里改走 `regenerate-polar`，用临时配置只重画当前列的两张雷达图，不回写主页面（窗口间不共享状态）。

### 应力曲线 Y 轴

上限按数据峰值向上取整到一个刻度间距，最高点刚好贴顶时再加一格，曲线不顶格；峰值超过 1000 时刻度固定 100 步进，
不超过时由 matplotlib 自动选。实现在 `EdgeStressReporter.generate_stress_chart`。

### 沿滚子距离

Romax 报告以滚子中点为原点，沿滚子距离有正有负（如 -81.9 ~ 82.0 mm）。应力曲线的 X 轴、等高线图的 Y 轴按数据范围画，
带负值时连负半边一起画；距离全部不小于 0 时才从 0 开始。实现在 `EdgeStressReporter` 的 `generate_stress_chart`、
`generate_contour_chart`。

### 中文字体

matplotlib 用 SimHei（`reporter.py` 顶部设置）。安装包面向 Windows；机器上没有 SimHei 时图里的中文显示成方块。
SimHei 里没有 Unicode 减号，同一处关掉 `axes.unicode_minus`，负数刻度用 ASCII 连字符，不然显示成方块。

## 接口与页面

| 方法 | 路径 | 用途 |
|---|---|---|
| WS | `/ws/parse` | 发文件列表和参数，逐文件推 `progress` 和 `fileDone` / `fileSkipped`，全部完成推 `done`，出错推 `error` |
| GET | `/api/chart-data` | 某文件某列某滚道的 Plotly 数据（原始 + 去峰），只读缓存、不写文件 |
| POST | `/api/update-stress-point` | 改一个去峰后的应力值并重画相关文件 |
| POST | `/api/regenerate-polar` | 按新的径向最小值重画该列两张雷达图 |

请求和响应模型见 `serializers.py` 与 `api/edgeStress.ts`。`fileDone`、`fileSkipped` 用 `index`（文件在请求
`filePaths` 里的下标）指认文件：`fileDone` 带这个文件解析出的列号和 `previewItems`（每列内圈中文应力曲线 PNG 的路径，
文件名悬停时显示缩略图）；`fileSkipped` 带没能解析的原因，文件表里标成「跳过」，原因写在文件名下面一行。
`done` 只带生成的文件列表。

- **主页面** `EdgeStressView.vue`：
  - 左边参数栏依次是数据文件（选择文件夹、清空）、输出目录、处理参数、报告图片（尺寸、雷达图最小值），
    底部「开始解析」；没选文件或没设保存路径时按钮不可用，下方提示缺什么。
  - 右边是文件表（状态、文件名、大小、列数、预览 / 移除），上方是进度条带；没文件时是整块可点的空状态。
  - 单个文件的状态由最近一次解析推出来：store 记下发给后端的路径顺序 `runPaths`，`fileDone` / `fileSkipped`
    按 `index` 对到路径存进 `fileResults`，有结果的文件是完成或跳过；没结果的按 `progress` 里的 `current` 和
    `processingName` 区分处理中和排队。
- **预览窗口** `ReportPreviewView.vue`：点文件行的预览打开，参数经 URL query 传入（`fileStem`、`outputDir`、
  `columns`），窗口机制见 Tauri Skill。顶栏选列号、切内 / 外滚道；三栏依次是 Plotly 交互图（标题栏「拖拽编辑」开关，
  开启后可拖点）、中英文应力曲线和等高线图、载荷与应力雷达图（标题栏调两个径向最小值）。
  滚道切换影响前两栏，不影响雷达图。报告图片（含放大弹窗）能拖进 Word、PPT、Excel，走原生文件拖拽，见 Tauri Skill。
